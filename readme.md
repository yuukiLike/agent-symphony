# Agent Symphony

> A symphony of agent actions.
>
> 让 Agent 的每一步，汇成音乐。

Agent Symphony 是一个把 Agent 执行过程变成音乐的趣味实验，计划以 npm 包的形式提供。

工具调用形成节奏，多个 Agent 交织成声部，等待留下间隔，错误改变音色。希望你不必一直盯着终端，也能听见执行中发生的变化。

当前处于探索与文档阶段，尚无可运行实现，也未发布 npm 包。以下描述都是待验证的方向。

## 为什么是交响乐

不同工具与子 Agent 像不同的乐器，连续操作形成乐句，并行执行展开多个声部。执行路径并非事先写好的乐谱，而是在运行中逐渐形成。

这个项目既探索声音，也借声音探索 Agent 是如何工作的。不必先成为一个严肃的监控产品，听起来有趣、能感知一些现象，就值得试试。

## 想听见什么

以下是声音映射的设想，不是已经实现的功能：

| 执行中发生的现象 | 声音中的表达 |
| --- | --- |
| 某类调用变得频繁 | 对应声音变得密集 |
| 相似操作反复出现 | 熟悉的乐句再次响起 |
| 多个 Agent 同时工作 | 不同声部重叠、交替 |
| 等待结果或用户输入 | 声音之间出现间隔，或使用等待音型 |
| 收到明确的错误事件 | 对应声音发生可辨认的变化 |
| 一轮执行结束或被中断 | 不同的收束方式 |

声音密集不代表有进展，安静不代表卡住，结束也不代表任务正确。项目只呈现可观测的现象，不主动告警，不替用户判断原因与好坏。

## 三个探索方向

- 听执行：用节奏、密度与声部感知单个或多个 Agent 的活动。
- 重放执行：记录可观测事件，回听一次任务，也试验不同的声音映射。
- 对照执行：同一个任务运行多次，听见调用、重复、等待与并行上的差异。

Hooks 是可能的接入点之一，不是 Agent 的全部行为。事件还可能来自 SDK 回调、事件流或日志；实际能听见什么，取决于接入方提供什么。

## 从哪里开始

先让一小段执行事件发出声音，听听调用变密、乐句重复和等待拉长是否真的可辨。接入平台、播放方式与 API 尚未确定。

- [探索方向](docs/exploration.md)：已确认的边界、声音假设与第一次实验。
- [事件来源](docs/events.md)：除了 tools、MCP 与 hooks，还可以观察什么。
