# Agent Symphony：Session 与 Skill 调查

日期：2026-09-21
状态：本文保留产品边界与调查目标形成时的设计提案，不是当前功能清单。后续已实现 dsh 接入与调查界面，实际范围和验证边界见 [项目首页](../../readme.md) 与 [验证记录](../verification.md)。
承接：[直接听见执行](direct-execution-sound.md)。

## 用户明确的方向

- 直接把 agent 的执行过程转成可辨认的声音，保持小型工具的定位，面向 Codex、dsh、Claude Code、Pi 等宿主。
- 清楚记录并展示某个 session 的调用过程，清楚切换 sessions。
- 「控制力」指对查看、聆听和调查范围的掌控。用户明确说：「它不会影响 agent 的执行，它只是清晰地记录 agent 的执行过程」。
- 用户可以指定想调查的 skill；指定是调查与聚焦，不是触发 skill 执行。
- hooks、tools、MCP 是用户列举的例子，不能成为观察范围的上限。

## 核心体验

同一份可追溯的执行记录同时驱动时间线、关系展示和声音。用户随时知道正在看哪个 session、聚焦什么、听的是实况还是记录中的哪一段。

声音与记录能够互相定位：播放时突出对应事件；点选事件后可查看细节并回听前后片段。若声音把多个密集事件聚合成一簇，定位展示整组事件，不假装一个声音只对应一次调用。

## 观察完整执行，而非只列接口名称

下面是事件模型应容纳的现象，不是已支持的采集清单。实际可见范围由宿主、接入方式和用户允许的记录范围决定。

| 观察层次 | 可能存在的可观测事实 |
| --- | --- |
| 任务与执行生命周期 | 用户输入、session、轮次、公开计划及其变更、启动、返回、取消、结束 |
| 指令与上下文 | 指令／skill 的读取或加载、公开报告的使用、检索与记忆访问、上下文压缩与恢复 |
| 模型活动 | 请求／响应边界、公开输出或公开推理摘要、已报告的 token 用量、错误及限流 |
| 行动与外部交互 | 工具与命令、进程、文件读写、搜索、浏览器／应用操作、MCP 工具和资源交互 |
| 协作与控制流 | 子 agent 创建、委派、交接、已报告的依赖、等待外部结果、请求用户输入／授权、重试 |
| 产物与结果 | 文件变化、命令结果、校验／测试结果、生成产物、最后回复与终止状态 |

来源未公开的内部推理不被伪造为可见事件。没有新事件只能表达观测空白，不能据此推断正在思考或已经卡住。

Hook 常是观察入口，也可能真的执行了独立脚本；MCP 常是交互方式。这些维度与「做了什么」分别记录。一次 MCP 工具调用和它的开始／结束 hook 可以描述同一操作，不能因有多个标签或来源而重复统计。只有关联证据足够时才合并；关联不足的原始记录保持独立并标出未知。

## Session 的身份与过程

- Session 列表显示任务简称、宿主、短 ID、来源报告的状态；相同标题也能区分。底层身份包含足以区分宿主实例和原生 session 的来源信息。
- 当前视图顶部持续显示 session 身份、调查范围与声音模式。项目／目录等信息按需补充，颜色只作辅助。
- 来源提供轮次信息时按轮次组织记录；动作记录已观测到的开始、后续事件和返回，缺失边界保持未知。来源明确报告的子 agent 关系以可展开分支呈现。
- 默认看得见执行者、动作名称、对象摘要、起止和结果。来源时间可靠时显示耗时；只有开始而没有返回时显示「尚未返回」，不用该状态证明进程持续运行。
- 选中事件再看来源已提供且允许展示的参数、输出、变化和错误。未采集内容明确显示缺失，不默认扩展成保存全部提示词和输出。
- 记录区停止自动滚动后提供「回到最新」。正在查看的历史事件与正在发声的现场事件分别标记。

## 指定一个 Skill 进行调查

1. 用户选择 skill 名称及可区分的来源身份；同名但不同来源的 skill 不混为一项。可用时保留版本或内容标识。
2. 先找到可观测的引入／提及／使用证据。明确报告使用实例和边界时，可进一步选择第几次使用；只读取过 SKILL.md 时，展示读取证据，不凭空建立一个完整调用实例。
3. 聚焦有依据关联的事件、调用、协作与产物，保留前后文入口。一个动作可以与多份指令有关，不能强迫它只有一个「当前 skill」。
4. 明确关联、推断线索和未归属记录分开显示，随时可以查看关系依据。时间相邻不能自动视为归属；缺失 skill 结束边界时不编造精确持续时间。
5. 筛选保留完整操作的开始与返回；有证据的父子调用可以展开，不能把子 agent 的全部活动自动归给父 agent 正在调查的 skill。
6. 过滤只改变所见所听，完整观测记录仍可恢复。默认聆听明确关联的活动；调查未归属片段时，声音表达所选事件，不把其归属改写为已知。

可回答的调查问题包括：何处引入该 skill；哪一次已报告使用关联了哪些动作；哪里出现等待、明确失败或重复调用；产生了哪些已记录的产物。只有提及或读取证据时，仍能定位和回听附近过程，但不声称已记录完整 skill 执行。

## 清楚地切换 Session

默认一个 session 获得声音焦点，查看与监听跟随 session 选择。

- 从 A 切到 B 时，标题、列表选中态、调查范围和声音来源一起切换。A 的余音短暂平滑收住，尚未播放的声音任务取消，真实记录继续保留。
- B 从实时接收位置开始被聆听。历史补齐只更新记录，不补演成新动作；切入前已经发起的调用不重放起音。
- A 的迟到返回仍更新 A，不串入 B 的时间线或声音。待处理与新事件信息保留在 A 的列表项。
- 切回 A，恢复其筛选、查看位置、选中事件和分支展开状态，同时明确提示后续更新。历史回放不自行恢复。
- 切换 session、选择 skill、静音或回放都不会向 agent 发送执行控制。

## 区分历史查看、回放和实况

查看旧事件仍可聆听同一 session 的实况；只有明确选择回放才播放记录。回放持续显示 session、调查范围和记录时间，现场事件继续记录但不混入声音。

回到实时从当前接收位置继续，不补播积压事件。切换 session 会结束此前回放；若新 session 已结束或连接不可用，显示该事实并保持安静，回放由用户明确触发。静默本身不用于推断结束或连接状态。

## 保持小工具的形态

一个 session 列表、一份当前执行记录、一个可切换的调查范围，以及按需展开的证据详情。Skill 是首先支持的调查入口；同一记录将来也可按 agent、调用、文件／产物或某段时间聚焦，不另建一套数据或大面板。

采集路径保持旁观，记录／播放故障不得阻塞执行或改变决策。实际开销、hook 失败行为和事件覆盖在接入时验证；不能仅凭使用 hook 就承诺完全无影响。四宿主公开 API 已完成本轮 [配置与事件核查](../research/agent-config-comparison.md)，dsh 已确认为 DeepSeek Harness，并在后续完成 [隔离宿主验证](../verification.md)；生产覆盖和普遍开销保证仍不在验证范围内。逐 hook 配声、接入差异与观测边界见 [观察与声音配置](observation-and-sound-config.md)。

## 下一份验证成果

交互草图用明确标记的模拟数据验证 session 切换、skill 聚焦、事件详情和实况／回放标记，不连接真实 agent，不发声。随后让同一份模拟事件同时驱动声音和视图，试听检查是否能从听到的变化定位到真实事件。

关键场景：

1. 两个同名 session 可清楚区分；A 发起后切到 B，A 的失败只归 A。
2. 同一 skill 的两次可识别使用可以分别聚焦；只有文档读取时不会虚构使用边界。
3. 选择 skill 后仍能查看未归属及前后文，不会把时间邻近误认为因果。
4. Hook、工具与 MCP 信息不会被当成三份相同操作；关联不明时保留原始证据。
5. 选中旧事件、回放、静音和切换 session 均不影响 agent 执行。
6. 一簇声音对应多事件时可回到整组记录，声音聚合不造成原始记录丢失。

这些是设计阶段的验收目标。后续 dsh 采集、音频实现与已经验证的场景见 [验证记录](../verification.md)，未在其中列出的提案不视为已实现。
