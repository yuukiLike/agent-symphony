- 延续已有边界：只表达可观测现象，声音不阻塞 agent，不凭活动频率判断进展，不默认采集完整内容。

## 体验提案

把每个可观察操作处理成一个有起点、可能有后续活动、可能有终点的发声对象。动作发生时出现声音；动作的间隔、返回顺序和交错构成节奏。音色相容、音量克制、余韵短，形成整体音乐感。

初版只区分少量活动类别。类别表达「在做哪一类动作」；同类音色中的音区或细微发音差异辅助区分 agent。声像只能是辅助线索，单声道仍要能使用。具体音色需要试听。

| 可观测事实 | 候选声音表达 | 不表达什么 |
| --- | --- | --- |
| 明确的读取／搜索类操作开始 | 轻短的拨弦或颗粒音 | 理解程度或找到答案 |
| 明确的写入／修改类操作开始 | 较结实的木质短音 | 修改已经成功或正确 |
| 命令／外部工具调用开始 | 短促低音，标记一个打开的操作 | 持续取得进展 |
| 操作返回 | 与起音对应的短收音 | 整项任务已完成 |
| 明确失败或取消 | 同一音色的短促变化 | 故障严重性或失败原因 |
| 明确请求用户操作 | 一次柔和且可辨认的提示，随后安静 | 用循环声催促用户 |
| 没有新事件 | 已有余韵衰减后安静 | 卡住、空闲或连接正常 |
| 明确回合结束 | 一个简短结束标记 | 任务经过验证、结果正确 |

无法可靠识别读写类别时，保留通用工具类别；不从工具名字或不完整命令片段臆测语义。

## 五条声音规则

1. **真实时间优先。** 不为了拍点改写执行先后，不加自动推进的鼓点，不积累很长的声音播放队列。播放有自然音频延迟，具体容许值在原型中测量。
2. **开始和返回配对。** 可用操作 ID 时，返回沿用同一发音特征。收到开始而未收到返回，只表示尚未观测到结束。长操作期间不自动生成「仍在工作」的持续音；只有来源明确报告的活动或进度事件能触发新的活动声音，这些事件也不保证任务取得实质进展。
3. **并行来自事件交错。** 有身份与操作关联信息时，保留不同来源及未闭合操作的区别。几个短音挨得近、声音余韵重叠，都不能单凭听觉证明同时执行；需用带关联信息的记录验证听感。缺少身份时不编造独立声部。
4. **重复来自重复事件。** 同类操作保持可辨认的音色。只有来源明确报告重试，才使用重试标记；重复调用本身不表示循环或无效工作。
5. **密集时限制声音，不拖慢执行。** 原型比较保留全部事件和短窗口聚合的听感。采用聚合后，音频只表达密度，不能承诺数出每次操作；必须明示聚合，并保留供核对的事件记录。设置音量上限和并发发声上限，具体参数由试听确定。

## 小工具的范围

- 一套声音规则和本地播放能力，各宿主分别适配可获得的事件。
- 界面包含 session 列表、当前执行记录、skill 调查范围和声音控制；连接状态与音频静默分开显示。切换和调查不控制 agent 执行。
- 第一份原型使用明确标记的模拟事件，不依赖先接通所有宿主。真实接入先选一个宿主，随后增加适配。
- 记录同时用于过程展示、session 切换、skill 调查、声音回放和试听迭代。更大规模的管理能力与自动执行质量分析仍不属于当前设计。
- 既有 README 中 npm 包仍是分发候选。发行载体、音频运行环境和发布流水线在选定首个宿主后确定，当前不承诺安装命令。

## 第一份可听成果

制作同一套音色下三段各约 30 秒的模拟执行声音：串行操作；两个已标识 agent 的交错执行；包含长等待、明确失败与再次调用的执行。保留毫秒时间与关联 ID 供对照。

试听先验证：开始与返回是否能配对；加入身份差异后是否更容易辨认不同来源；长间隔是否被误听成故障；失败变化是否可辨且不刺耳。随后连续播放 20 分钟的模拟工作，记录何时想静音、原因是什么。以上是实验任务，不是已经得到的结果或通过标准。

另做一次密集突发输入实验：确认音频不会持续落后执行，并评估限流后丢失了哪些可听细节。

## 待验证的问题

- 音色从木质／拨弦、电子脉冲或混合音色中选取，尚未确定。
- dsh 后续已确认为 DeepSeek Harness，接口与隔离联调见 [接入指南](../dsh-setup.md)；Codex、Claude Code 仍需针对实际接入版本验证。
- 声音类别、返回音的可辨性、长时间疲劳、并发容量与聚合窗口均需试听或测量，不把文字设计当作验证。
- 有结果却没有开始、事件乱序／重复、宿主连接中断时如何降级，在首个真实适配器设计时落实；未知状态不补造起音或结束音。
